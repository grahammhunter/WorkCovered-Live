# Work Covered Commercial Positioning and ROI Specification

## Objective

Rework the opening of the staging website so Work Covered is immediately understood as a premium website and technical-integration partner whose work helps established UK businesses win more suitable enquiries, respond faster and reduce repeated administration.

## Approved direction

Use the approved Direction A editorial hero rather than a conventional SaaS dashboard composition.

- Lead with: `Built to be chosen. Wired to respond.`
- Present the offer in this order: the website, the response, the follow-through.
- Keep the animated enquiry counter, but move it below the main hero composition so it does not compete with the editorial index.
- Label the counter as an illustration. It must not use `live`, `running now`, or any wording that implies the changing figures are customer results.
- Keep the existing Work Covered palette, typography and restrained motion language.

## Honest ROI narrative

Introduce the commercial logic before the detailed service sections.

- A stronger website can improve how quickly a suitable customer chooses the business.
- Faster answering can reduce avoidable enquiry loss when the team is occupied or unavailable.
- Joined-up systems can reduce repeated entry, chasing and hand-offs.
- The site must not claim a percentage uplift, guaranteed payback period or customer result that has not been verified.
- Explain that the assessment uses the buyer's own average job value, missed-enquiry pattern and admin time. If the arithmetic does not justify the work, Work Covered should say so.

## Service clarity

Use one naming system from the hero into the existing three-layer interaction:

1. `The website` — premium web design and build.
2. `The response` — web and voice assistance.
3. `The follow-through` — integration, CRM, booking and follow-up.

The first layer remains visually and verbally primary. AI is an enabling capability, not the identity of the business.

## Scope boundary

This phase changes only the `staging` branch deployed to `workcovered.co.uk`. It does not change `main` or `workcovered.com`.

The following require separate decisions and are excluded:

- Which real customer websites and approved results replace the current proof placeholders.
- The final GHL form endpoint, field mapping, consent record and automation route.
- Final privacy policy, terms and contact destinations.
- Promotion of the staged commit to `.com`.

## Acceptance criteria

1. The hero uses the approved Direction A headline and editorial index.
2. The animated counter remains operational but is clearly labelled illustrative and contains no live-data claim.
3. A commercial-return section appears before the detailed service explanation.
4. ROI copy uses buyer-specific inputs and makes no unsupported promise.
5. The three service layers use the same website, response and follow-through naming throughout.
6. Existing demo, navigation, form simulation and accessibility behaviour continue to pass the automated suite.
7. The staged desktop page has no horizontal overflow, clipping or obvious collision at the primary laptop viewport.
